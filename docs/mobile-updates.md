# Обновления Android

Приложение использует существующий проект Expo `4f39246d-f506-4126-9019-4e1a4ebb1586`, канал `production`, `expo-updates` и политику совместимости `appVersion`.

## Поведение на телефоне

- При запуске открывается сохранённая рабочая версия без ожидания сети (`fallbackToCacheTimeout: 0`).
- Совместимое обновление загружается автоматически. Проверка также повторяется при возвращении в приложение, не чаще раза в 15 минут после успешной проверки; после сетевой ошибки повтор разрешён через минуту.
- Активный экран не перезапускается после завершения загрузки. Обновление применяется при сворачивании или следующем холодном запуске. Повторные проверки не запускаются одновременно.
- Ошибка сети оставляет рабочую версию, сохранённый каталог и аккаунт на месте. Поддерживаются штатный откат Expo к встроенной версии и повтор после неудачного перезапуска.
- Изменения интерфейса и JavaScript могут доставляться без переустановки. Изменения нативных модулей, разрешений Android и других частей установочного пакета требуют нового APK и обычного подтверждения установки Android. Обход подтверждения установки не используется.

## Публикация совместимого обновления

1. Выполнить `node --test scripts/app-updates.test.mjs scripts/listing-sources.test.mjs scripts/catalog-offers.test.mjs` и `npx tsc --noEmit`.
2. Проверить интерфейс и изменения; убедиться, что нативные зависимости и настройки установленной версии не менялись.
3. При выпуске только совместимых изменений **не увеличивать `expo.version`**: это версия совместимости установленного APK, не номер каждой правки сайта. Для нового APK с изменённой нативной частью увеличить `expo.version` и Android `versionCode`.
4. Из учётной записи Expo с существующим доступом к проекту выполнить `npm run update:android -- --message "Описание изменения"`. Для автоматизированного запуска можно добавить `--non-interactive`, если аутентификация уже настроена. Секреты в репозиторий и приложение не добавлять.
5. Проверить опубликованную группу обновлений, соответствие канала `production` и версии совместимости. Проверить получение на реальном установленном APK: запуск, загрузка, сворачивание/повторный запуск, сохранность аккаунта и свежесть каталога. Успех сборки сам по себе не подтверждает доставку обновления.

Автоматическая загрузка на телефоне требует **публикации** обновления в Expo. Обычная публикация сайта на GitHub Pages не создаёт обновление Android. Старые APK с другой `expo.version` не получают обновления этой версии совместимости; для них нужен отдельный проверенный совместимый выпуск либо установка нового APK один раз.

Документация: https://docs.expo.dev/eas-update/deployment/ и https://docs.expo.dev/eas-update/runtime-versions/.
